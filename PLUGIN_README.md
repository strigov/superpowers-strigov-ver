# superpowers-strigov-ver

Personal Claude Code plugin assembled from:
Current repo/plugin version: `0.13.0`.

- **`dev-orchestrator`** — multi-model subagent-driven workflow with a pinned model + effort per role (Opus xhigh plan + Opus high revisions + GPT-6 Astra xhigh plan-review loop + GLM-5.3-Flash max implement via Z.ai's ZCode CLI (`bin/zcode-dispatch`) with GPT-6 Luna max availability fallback and GPT-6.1 Sol xhigh for SECURITY/DATA_LOSS phases and reasoning escalation (channel ladder per phase, `risk_phases` frontmatter map, gate-stall diagnosis) + Sonnet medium verification gate + per-phase fused review: Opus high spec+quality (xhigh on SECURITY/DATA_LOSS phases and in round 4) and Astra high control, both fed a pre-baked review package via `bin/review-package`; file-based implementer reports; Opus high BLOCKED diagnosis; final whole-branch Opus xhigh review before archival, cap=2, Astra xhigh fallback; review synthesis; plan-marked parallel groups run as 2 concurrent tracks in git worktrees; auto-commit, fused loop cap=4 with anti-pingpong / no-progress guards; thread-addressed Codex resume via `--resume-task`; `ultra` effort strictly user-initiated).
- **`codex-invocation`** — reference recipe for calling Codex via the `bin/codex-dispatch` wrapper around the vendored `codex-companion.mjs` (background mode + Monitor polling; bypasses the silent auto-reject on standard Agent/`codex exec` paths and pins the default model to `gpt-6.1-sol` to block backend auto-downgrade to spark; per-role GPT-6 routing table included).
- **`zcode-invocation`** — reference recipe for running GLM-5.3-Flash at `max` through Z.ai's own ZCode CLI via the `bin/zcode-dispatch` wrapper (`bin/lib/zcode-dispatch.mjs`): background jobs `zt-NNNN` + Monitor polling, `doctor` / `doctor --probe`, errorClass → action table, sandbox warning, compliance stance, kill switch `SP_IMPLEMENTER` (`luna`, or a profile of the user's agent-dispatch `config.json` that does not run in the session; other values are ignored, as before; the wrapper itself refuses only `luna`).
- **`agent-invocation`** — reference recipe for `bin/agent-dispatch` (`bin/lib/agent-dispatch.mjs` on the shared job core `bin/lib/agent-core.mjs`): every pipeline role is a route whose built-in chain is the dev-orchestrator Model split table; an optional `~/.claude/plugins/data/superpowers-strigov-ver-agents/config.json` rebinds roles to user profiles (harness + auth + model + effort). `route` / `route --all`, the `channels` marker, jobs by id prefix (`ct-`/`oc-`/`pi-`/`dt-` core, `zt-` ZCode, `task-` Codex), failure classes, headless implementer and reviewer preambles. ZCode and Codex profiles pass through to their wrappers unchanged; core adapters for `claude -p`, `dsh`, OpenCode and pi; any role — the in-session ones included — can run on any profile (`tree-state` checks that no-edit roles left the tree alone). Runs natively on Windows too: a C# helper (`bin/lib/win/agent-proc.cs`, compiled once with the system csc.exe of .NET Framework 4) supplies process identity and runs each harness in a Job Object, so a cancel, a timeout or a dying runner ends the whole tree (tests: `tests/test-agent-core-windows.sh`).
- **`architecture-memory`** — maintain `docs/ARCHI.md`, a persistent tool-agnostic architecture memory with token budget, update discipline, and compaction script. Adapted from TRIP-workflow.
- 12 upstream skills copied from `superpowers` (Jesse Vincent / obra), namespace-stripped: `brainstorming`, `dispatching-parallel-agents`, `executing-plans`, `finishing-a-development-branch`, `receiving-code-review`, `requesting-code-review`, `systematic-debugging`, `test-driven-development`, `using-git-worktrees`, `verification-before-completion`, `writing-plans`, `writing-skills`. `brainstorming` extended to delegate spec/ADR writing to Opus xhigh (revisions Opus high) and spec review to Codex Astra xhigh; `writing-plans` delegates plan writing to Opus xhigh and plan review to Codex Astra xhigh (loop cap=4) — the same writer/reviewer pair as dev-orchestrator Steps 1–2.
- `/dev` slash command — explicit entry point for `dev-orchestrator`; with no task, it resumes an in-progress plan.
- **Manual-only invocation** — every pipeline skill (all of the above, including `zcode-invocation`, except the four discipline skills `systematic-debugging`, `test-driven-development`, `verification-before-completion`, `receiving-code-review`) and `/dev` carry `disable-model-invocation: true`, so the model neither sees nor loads them on its own. The user starts the pipeline (`/dev`, `/superpowers-strigov-ver:<skill>`); skills chain by `Read` of `../<name>/SKILL.md` because the Skill tool refuses them. A SessionStart hook (`hooks/hooks.json` → `bin/pipeline-context`) stays silent unless the repo has an in-progress plan (it names the plan and the dev-orchestrator path for "continue") or a compaction/resume follows a pipeline skill (it points at the skill to re-read).

**Code review** is dispatched as an Opus subagent via `Agent(subagent_type="general-purpose", model="opus", effort="high", ...)` — see `skills/requesting-code-review/`. The standalone `code-reviewer` agent type from upstream was removed; start this manual-only pipeline skill explicitly with `/superpowers-strigov-ver:requesting-code-review` or read `skills/requesting-code-review/SKILL.md`.

**Not included:** upstream `subagent-driven-development` (replaced by `dev-orchestrator`), `using-superpowers` (aggressive MUST-directive was not wanted), the SessionStart hook that injected `using-superpowers` (the plugin's own SessionStart hook above is unrelated and silent by default).

## Install on another machine

Copy this directory to the target machine, then:

```
/plugin marketplace add ~/superpowers-strigov-ver
/plugin install superpowers-strigov-ver
/reload-plugins
```

(Adjust the path if you put it elsewhere.)

## Machine-specific assumptions

The Codex companion runtime is **vendored** under `vendor/codex-companion/` (Apache-2.0, copyright OpenAI; sourced from `github.com/openai/codex-plugin-cc`). All dispatch goes through the `bin/codex-dispatch` wrapper, which (1) resolves the script from either the marketplace install path or the local dev tree, (2) pins state to `~/.claude/plugins/data/superpowers-strigov-ver-codex`, and (3) auto-injects `--model gpt-6.1-sol` (overridable via `CODEX_DEFAULT_MODEL=...` or an explicit `--model` flag) for `task`/`review`/`adversarial-review` so the backend can't auto-downgrade to spark. You do **not** need OpenAI's `codex-plugin-cc` installed.

The only external dependency is the standalone `codex` CLI (`npm install -g @openai/codex`) and a one-time `!codex login` per machine.

The GLM channel runs on macOS and Linux. It assumes the ZCode app — `/Applications/ZCode.app` on macOS, `/opt/ZCode` on Linux (or `ZCODE_APP`) — with its embedded Agent CLI at `<resources>/glm/zcode.cjs` (`<resources>` = `Contents/Resources` in the macOS bundle, `resources/` elsewhere; the wrapper runs that file with the system `node` and never uses a `zcode` on `PATH`, which on Linux is the desktop launcher) and its version in `Info.plist` (macOS) or `resources/app.asar` (Linux); Linux also needs `flock(1)` from util-linux for the config lock. On Linux, Z.ai's official `.deb` / `.rpm` (beta, <https://zcode.z.ai>) installs into `/opt/ZCode`; an extracted `.AppImage` works with `ZCODE_APP=<dir>/squashfs-root`. It is run under the system `node` (major version at least `VERIFIED_NODE_MAJOR` in `bin/lib/zcode-dispatch.mjs`), with the user's Coding Plan API key stored via `zcode-dispatch api-key set` (a provider of ZCode's own "Z.ai Coding Plan" template in the wrapper's personal provider config, mode 0600; no expiry). The CLI's OAuth login is not used: it keeps no refresh token and lasts about an hour (see `zcode-invocation`). `bin/zcode-dispatch` keeps its job state, its own personal provider config (the model pin and the API key) and the CLI's own credentials and state (`cli-home`, passed as `ZCODE_DATA_BASE_DIR` plus storage, session-database and log overrides under it: the CLI's credentials, plugins, sessions and logs) under `~/.claude/plugins/data/superpowers-strigov-ver-zcode`, and never edits `~/.zcode`, which the ZCode desktop app uses; the CLI itself still reads its user config `~/.zcode/cli/config.json`, which has no override. Without the ZCode app (or on Windows, not supported yet), `zcode-dispatch doctor` fails and dev-orchestrator implements on Codex Luna max (announced).

The wrapper gives the CLI an allowlisted environment, including `PATH`, `HOME` and `ZCODE_HTTP_PROXY`; extra variable names can be opted in with `ZCODE_ENV_PASSTHROUGH="NAME1,NAME2"`. Its cli-home paths always override inherited values, and `ZCODE_SESSION_DB` is dropped.

To bump the vendored runtime, replace the contents of `vendor/codex-companion/{scripts,prompts,schemas}` from a newer `openai/codex-plugin-cc` release and update `vendor/codex-companion/VERSION` — then re-apply the local patches listed in that file (notably the `--resume-task` flag and the `max`/`ultra` reasoning efforts).
